# Settled synth envelope rate tables, the amp chain limit above 1, and the error of the stale tables per program

**Checked:** 2026-11-21.
**Sources:** `tools/synth_scaling_crosscheck.py` (published closed forms of the open-source OpenNord project, AGPL-3.0, `src/lib/ns4/synth-scaling.ts`; numbers only, no code copied), `tools/synth_env_rates.py` (`sweep`, `compare`, `emit`, `census`), `tools/synth_env_limit.py`, `tools/synth_env_programs.py`, `crates/nord-tools/src/bin/synth_env_census.rs`, `synth_env_native.rs` (`--rates`, `--sustain-half`), ORG core 2 `sharc-sys` oracle (`target/synth_env/sram/core2_sram.bin`, capture `Bank_A__12dB_Sweep.txt.gz`), data `data/synth-env-rates-settled.csv` (129 indexes), `data/synth-env-amp-limit.csv` (592 rows), `data/synth-env-programs.csv` (160 rows), `data/synth-env-rate-table.csv` (the stale sweep), [synth-env-law](synth-env-law.md) (D210), [synth-adr-and-strip-law](synth-adr-and-strip-law.md), [synth-stage-equations](synth-stage-equations.md) s7, D212.
**Question:** D210 found that the default attack table is a stale 3 pass sweep and left three items open: the same check of the decay / release table, the amp chain peak above 1 at `g >= 107`, and how much the stale tables cost per program.

## 1. Method: read the installer words after the 16 pass refresh

The installer (`0x12720F..0x127281`) turns each ADR strip word into a coefficient and stores it at `DM(0xC0E21 / 0E24 / 0E28)` (amp attack / decay / release; filter `0E35..`, osc `0E41..`) only on its apply pass, every 16th pass. The old sweep (`synth-env-rate-table.csv`, D130) read 3 passes after each poke, so over most of the range it held the value of an earlier index.

`python tools/synth_env_rates.py sweep` pokes the nine ADR words with one index (top byte, all nine words equal) at pass 0, runs 64 passes with the core 2 recall load, taps the nine installer words every pass and keeps the last pass after checking that the row did not move over the last 32 passes. 129 runs (index -64..=64), about 0.25 s each. Checks in the tool: the amp, filter and osc chains agree at every index; the committed rows are `data/synth-env-rates-settled.csv` (`attack_coeff`, `decay_coeff`, `release_coeff`, float32 bits).

## 3. Amp chain limit above 1 (VERIFIED law, mechanism not located)

The chain clamps its level to `L = DM(F - 22)` (`F = 0xC1188`, `0xC1172`; the envelope loop `0x71EB..`, [synth-adr-and-strip-law](synth-adr-and-strip-law.md) s2 writes `L = 1.0` for the amp chain, `DM(0xC1370)` for chain 2). Tapped every pass: `L` is 4.0 before any key and becomes `1 + 0.2 k` at the key on (`1.0` for every `g <= 98`). The filter chain limit `DM(0xC1370)` stays 1.0 and the filter chain peak is 1.0 in every run. The amp peak is exactly `L`: the attack ramp is not cut at 1 but at `L`, then the decay record falls to 0.5.

| Quantity | Law |
|---|---|
| `G` | key byte, 128 for `g = 127` |
| `e` | `(w * G) >> 7` for a negative attack word `w` (the D210 amp attack index), `w` otherwise |
| `e0` | `(-64 * G) >> 7` |
| `d` | decay word (not scaled) |
| `k` | `max(0, ((G - 97) >> 1) - (e - e0) - (d + 64))` |
| `L` | `1 + 0.2 k` |

`python tools/synth_env_limit.py grid` (592 oracle rows: keys 60 / 36 / 84, `g` in 60, 98, 99, 104, 110, 118, 126, 127, attack words -64 .. 0 (9), decay words -64 .. 0 (8), release -64) and `check`: **592 of 592 rows** equal the law (test `test_committed_oracle_grid_matches_the_law_on_every_row`). Properties:

- `L > 1` needs `g >= 99` **and** a fast attack word **and** a fast decay word: the sum `(e - e0) + (d + 64)` must stay below `(G - 97) >> 1` (at most 15). `g = 127`: attack -64 with decay -64 gives 4.0, attack -50 with decay -64 gives 1.2, decay -50 with attack -64 gives 1.2; Hold and any decay word above -49 give 1.0. The release word does not matter.
- Maximum `L = 4.0` (+12 dB of overshoot on the chain output), at `g = 127`; the staircase in `g` has steps of 0.2 every two key bytes (`g` 99 and 100 give 1.2, ..., 125 and 126 give 3.8, 127 gives 4.0).
- Which ARM or DSP code writes the word is not found; the formula is a fit, with exact agreement on the grid but no derivation. The audio reading is ASSUMED: the layer gain stage behind the chain is not isolated, so a chain level above 1 may or may not reach the output unclipped.
- **No factory program can reach it.** The 384 factory programs hold 635 enabled synth layers with stored knobs (351 programs); 0 of the 635 amp envelopes have `k > 0` at `g = 110` or `g = 127` (the 300 layers with amp attack -64 all have a slow or Hold decay: 534 of 635 amp decays are Hold). The native chain clamps at 1; the gap only matters for a user edit with a fast attack and a fast decay on a hard key.

Native port: not done (no factory program uses it, the audio effect is ASSUMED); `amp_limit` in `tools/synth_env_limit.py` is the reference.

## 4. Per program: native against oracle, stale against settled tables

`python tools/synth_env_programs.py run` takes 40 synth layers spread evenly over the census order (every 15th of the 635 layers: 40 different programs of banks A to F), injects each layer's stored amp and filter rate knobs as ADR words (the `synth_env_trace` path, key byte 127 so the amp attack is unscaled, 12,000 passes held, 6,000 after the key off) and compares the amp and filter chain levels per pass with the native chains. Both native runs use `--sustain-half` (both decay records stop at 0.5, the oracle value), so only the rate tables differ. Error = mean absolute level difference over the 18,300 passes.

| Chain | Tables | layers | mean error: mean / median / max | layers with mean error > 0.01 | release half time log2 error, median |
|---|---|---|---|---|---|
| amp | stale (default) | 40 | 0.0171 / 0.0148 / 0.0631 | 25 | 0.21 (15 % off) |
| amp | settled | 40 | 0.0009 / 0.0010 / 0.0014 | 0 | 0.00 |
| filter | stale (default) | 40 | 0.0183 / 0.0131 / 0.1353 | 27 | 0.00 (34 layers measured) |
| filter | settled | 40 | 0.00024 / 0.00008 / 0.00096 | 0 | 0.00 |

Settled is no worse than stale on any of the 80 chain rows (test `test_committed_programs_csv_settled_beats_legacy_on_every_layer`). The residue of the settled amp error (0.001) is the first pass of the attack (the oracle ramp starts one pass later than the native one) and the float32 step of the record. No amp chain of the sample overshoots 1.

## 5. Default flip proposal (not applied; owner approval, D22)

Evidence for the owner: the settled tables replace a table that is off by more than 2 % at 104 of 129 indexes for attack and for decay / release; the settled tables reproduce the oracle chain at 0.001 mean error on 40 sampled layers against 0.017 .. 0.018, with 0 of 80 chain rows worse. Not shown: a clip score on the hardware recordings (the owner's rule D136 / D22 asks a clip check before a default flip), and the audible effect of the sustain level 0.5 (separate, ASSUMED).

The flip is one line: `DEFAULT_TABLES` in `crates/nord-core/src/synth/fw_env_rates.rs` from `LEGACY_TABLES` to `SETTLED_TABLES`; `LEGACY_TABLES` stays as the legacy switch (a `--legacy-synth-env-rates` flag would select it). It changes every default synth render: re-baseline `render_hash`, and update the tests `default_tables_are_still_the_legacy_sweep` and `tables_equal_the_research_csv` scope. Until then the settled tables are read by the opt-in `--synth-fw-adr-law` (together with the velocity scaled amp attack and the 0.5 sustain).

## 6. Implications

- The decay / release table has the same defect as the attack table; the stale sweep should not be used for any time derived claim (`attack_time_passes`, the `strip_map` inverse, the display-time notes of `fw_knob_laws.rs` "reproduce the displayed times" were checked on plateau anchors).
- The amp overshoot is a documented corner (no factory program, +12 dB at most on the chain, audio ASSUMED).

## 7. Follow-ups

- Clip score of the settled tables (and of `--synth-fw-adr-law`) on the hardware clips, then the owner's flip decision.
- Invert the settled tables in `strip_map.rs` for the panel path (display time to index).
- Locate the writer of `DM(F - 22)` and port the limit if a user program can reach it; decide whether the layer gain stage clips it.
- The Hold decay word (knob 127 gives index 63 in the oracle, 64 with the native 1.0 threshold): the oracle holds at 0.5 with a 4.8e-6 rate, the default native Hold keeps 1.0.

## 8. Cross-check against published closed forms (independent corroboration, not VERIFIED)

Conclusions: the stale 3-pass tables disagree with the independent fit by up to 2.5 times; the settled tables agree with it to under 1 %, which corroborates (but does not replace) the oracle measurement. The resonance disagreement is closed by D214 (the quadratic is table `D`, LP12, not `B`); the earlier open reading was: either their fit covers only the low half of the table (probably they fitted the displayed range or a different kernel table) or the resonance index law differs; keep our table.
