# FX default parameters per block: firmware against emulator

- **Checked:** 2026-11-15
- **Sources (local, never committed):** the ARM edit-parameter table `docs/research/arm-edit-params.csv` (`default` column of every `Edt_Effects_*` and `Edt_OrgCom_kEffectsLeslie*` id, the D97 method), `fx/mod.rs` (`LayerFxChain::new`), `cbin/fx_preset.rs` (`FxDecoded::default`), `organ/mod.rs` (Leslie drive). Derived data committed: [data/fx-defaults.csv](data/fx-defaults.csv) (44 rows), generated by `python tools/fx_defaults.py` (`--check` fails on a stale CSV or Rust table).
- **Question:** audio item 13 of [audio-remaining](audio-remaining.md): do the emulator's FX default values match the firmware default words for amp, EQ, compressor, delay, reverb, Mod 1 / Mod 2 (chorus, flanger, phaser, ensemble, vibe), rotary and drive?

Tags follow `.agents/rules/provenance-in-code.md`.

## 1. Method

Each `Edt_*` default word is converted with the law the emulator already uses for that parameter:

| Unit | Law | Source |
|---|---|---|
| knob fraction | `v / 127` | `fx/fw_map.rs` |
| delay time | `kDlyRateClkDiv` through the 1501-entry table, fractional index = ms (default word 11008 = 250 ms) | `fx/fw_delay_time.rs` |
| mid frequency | `EQ_FREQ_HZ[v]` (default 64 = 999 Hz) | `fx/tables.rs` |
| EQ gain | 0.25 dB per count | `fx/fw_eq.rs` |
| reverb amount | the word is compared as the knob fraction (the wet law `x^2 (2 - x)`, `x = v / 128`, is D64) | `fx/fw_map.rs` |

Emulator defaults are read from the Rust source by the generator, so the table cannot drift from the code.

## 2. Result

| Status | Meaning |
|---|---|
| match (21 rows) | amp type, EQ gains and mid frequency (999 against 1000 Hz), drive, comp / delay enables, ping-pong, delay mode and filter, reverb colour and type, Mod 1 type, Leslie enable |
| differs (17 rows) | listed below |
| representation (4 rows) | the firmware has an enable flag (`kFx1Enable`, `kFx2Enable`, `kAmpEnable`, `kRvbEnable`, all 0); the engine encodes Off in the type or has no enable (reverb); not a parameter difference |
| not-compared (2 rows) | the Mod 1 / Mod 2 rate in Hz: the law depends on the type |

Fields that differ (firmware against emulator, knob fraction unless noted):

| Field | Firmware | Emulator chain | Emulator preset decoder |
|---|---|---|---|
| mod1 / mod2 amount | 0.504 | 0.40 / 0.35 | 0.50 / 0.40 |
| mod1 / mod2 rate | 0.504 | n/a | 0.40 / 0.30 |
| mod2 type | 0 (PHAS) | 4 | 4 |
| comp amount | 0.748 | 0 | 0 |
| delay time | 250 ms | 375 ms | 0.25 normalised (firmware 0.672) |
| delay mix / feedback | 0.504 / 0.504 | 0.25 / 0.35 | 0 / 0.30 |
| reverb amount | 0.299 | 0.15 | 0 |
| rotary drive | 0 | 0.2 | n/a |

The 8 chain fields (`mod1_amount`, `mod2_amount`, `eq_mid_freq_hz`, `comp_amount`, `delay_time_ms`, `delay_mix`, `delay_feedback`, `reverb_mix`) go into `fx/fw_defaults_table.rs`; `--fx-defaults-firmware` writes them (`LayerFxChain::apply_firmware_defaults`). Tags: the default words are VERIFIED (read from the table); that a fresh hardware layer starts from them is ASSUMED, no init-patch clip exists.

## 3. Why no default flips

- `apply_fx_chain` overwrites every FX field when a program loads, so the defaults reach audio only for an engine with no program (unit tests, a bare engine).
- The compressor and delay stay disabled in both (`comp_enabled` 0, `delay_enabled` 0), so their amounts and times are inaudible until switched on.
- No hardware clip of an init patch exists. D22 needs end-to-end evidence, so `render_hash` is unchanged and the flag is opt-in.

## Implications

- The emulator's FX default values were chosen by ear (ASSUMED); the firmware starts every knob near the middle (0.504 = 64/127) and the reverb at 0.299.
- Opt-in `--fx-defaults-firmware` gives the firmware starting point for an A/B on a bare engine.
